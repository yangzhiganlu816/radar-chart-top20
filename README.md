# 雷达图TOP20模板

**简体中文** · [English](README.en.md)

一个做多维排名展示的单文件网页模板。雷达图 + 逐条过场 + 自动结算最强项，20 个条目、6 个维度开箱可用。

打开 `index.html` 就能跑。不用构建，不用装依赖，不联网，也不需要服务器。

![效果预览](preview.png)

## 它是从哪来的

最初是为了做一个年度歌手榜单：20 位歌手横向对比，要有播放式的过场，还要把每个人的最强项突出出来。做完之后我把领域相关的部分抽掉，剩下的就是现在这个模板。

所以它适合任何「一堆对象 × 一堆评分项」的展示——产品评测、方案对比、选品打分、能力雷达、游戏评分。只要你的数据能写成「每个对象在 N 个维度上各有一个分数」，就能用。

## 改成自己的内容

**不写代码的话**，看 [GUIDE.md](GUIDE.md)。里面有段可以直接复制给 AI 的提问模板，把你的数据填进去就行。

**写代码的话**，看 [TUTORIAL.md](TUTORIAL.md)。数据流、排序算法、图片管线、调试方法、常见坑都写清楚了。

要改的东西基本都集中在一个数组里，搜 `singersRawOrder` 就能找到。增删行即可，配色和默认文案会按顺序自动分配，不用改别处。

| 想改什么 | 搜这个 | 注意 |
|---|---|---|
| 条目名字和分数 | `singersRawOrder` | **改完记得改 `DATA_VERSION`**，见下方提醒 |
| 维度名称 | `dimNames` | 顺序要和 `points` 对应 |
| 维度说明文案 | `dimDescriptions` | 顺序同上 |
| 各维度权重 | `rankingWeightPercent` | 总和必须为 100 |
| 主题配色 | `themePalette` | 按顺序取色，改名增删都不会错位 |
| 默认成就文案 | `achievementDefaults` | 按索引取 |
| 统计区间 | `rankingPeriod` | 显示在开场规则页 |
| 雷达图刻度上限 | `RADAR_MAX_SCORE` | 默认 10 |

> ⚠️ **最容易踩的坑**：在代码里改了初始数据后，必须同时改 `DATA_VERSION`。页面启动时会比对版本号，不一致就清掉浏览器里的旧数据。不改的话，你改的数据会被用户本地的旧分数盖掉。

### 配图靠文件名匹配

条目照片不写在代码里，而是通过界面上的 📷 按钮加载，**按文件名自动对应到条目**。规则是：文件名去掉扩展名后要和条目名对得上。

- `条目1.jpg` → 能配上「条目1」
- `条目一.jpg` → **配不上**，中文数字不认
- `条目1 .jpg` → 可以，匹配时会忽略空格

一次可以选中整个文件夹批量加载，配不上的会跳过。想微调某一张（缩放、上下左右位置）就用面板里的裁剪功能，裁剪结果是 720×720 的正方形。

配好的照片只存在你自己的浏览器里，不会写进代码，也不会上传。

## 几个值得一提的地方

### BEST 不用手动标，但规则是明确的

加载时全量扫一遍，判定条件只有一条：**某个条目在任一维度上的分数，等于该维度的全场最高分**。满足就带 BEST 标记，并有专属过场动画。

几个边界情况值得先知道：

- **并列第一全都算。** 两个条目在同一维度并列最高，两个都是 BEST —— 不会按顺序硬挑一个。
- **整列为 0 不算。** 某个维度所有条目都是 0 分时没人会被标记，否则会一次冒出十几个 BEST。
- **只看单维度，不看总分。** 总分很高但没有任何一项排第一的条目，拿不到 BEST。
- **跟着你的编辑走。** 在页面上改了分数，判定立刻重算，不需要刷新。

### 雷达图会自己找大小和位置

每个条目的缩放比例和居中位置都是单独实时算出来的：先把数据多边形顶点和外围文字标签一起算成一个包围盒，再求出「刚好能放进画布」的最大缩放值，最后按包围盒中心把图形平移居中。所以图形不会顶到边框，也不会缩在角落。

有一点容易误解：**图形的实际半径不是分数除以满分的线性比例**。中低分段扩张得更快，8.5 分以上再拉长一段，让头部差距更外溢。这个映射只影响绘制半径，不改分数、不影响排名。

切换条目或编辑分数时，缩放和位移都是平滑过渡，不会跳变。

### 排名和显示走两套口径，这是刻意的

排名只认**整数加权分**：每个维度的分数先乘 100 取整，再乘权重累加。先取整是为了消掉浮点误差 —— 否则会出现「两个条目算出来数学上相等，但程序认为不等」导致的误排名，这类问题排查起来非常麻烦。同分则按标准竞赛规则并列（1, 2, 2, 4）。

而显示的总分是另一套三段线性映射，只在 8.5 分以上拉长斜率让头部更外溢。**这套映射永远不参与排名**，所以你可以放心调整视觉呈现，名次不会跟着变。

### 图片切换不掉帧

base64 数据一次性转成 blob URL，配合预解码和 LRU 缓存，再靠空闲时段逐个预取。二十张图来回切也不会卡。

## 数据存在哪

分数、成就文案、照片全部存在浏览器 localStorage，**不上传任何服务器**。界面上点「↺ 重置全部」可以清空。

存的键名如下，需要手动排查时用得上：

| key | 内容 |
|---|---|
| `radarChart_points` | 各条目分数 |
| `radarChart_honors` | 各条目成就文案 |
| `radarChart_achievements` | 可编辑成就 |
| `radarChart_portraits` | 条目卡片照片 |
| `radarChart_best_photos` | BEST 转场照片 |
| `radarChart_best_backgrounds` | BEST 背景图 |
| `radarChart_presentMode` | 展示模式的开关状态 |

### 存储上限：只有 5MB 左右

这是 localStorage 的硬限制，值得提前知道，因为**照片是主要占用**。

裁剪结果按 **JPEG** 存，720×720 一张约 90KB，二十张加起来不到 2MB —— 正常用够。不用 PNG 是因为同样尺寸的 PNG 单张能到 800KB，二十张就是 16MB，**实测第 8 张就开始写不进去了**。需要无损导出时用面板里的「下载 PNG」按钮，那条路径不受这个设置影响。

**万一真的存满**，状态栏会明确告诉你「没有保存成功」并给出当前用量，不会假装没事。处理顺序：

1. 先点「下载 PNG」把当前这张导出到电脑上，别丢了
2. 用照片面板的「恢复默认照片」清掉几张不用的
3. 重新上传

如果确实需要放很多大图，建议改用外部图片 URL，或者拆成几个文件分开演示。localStorage 不适合当图片仓库。

### 换设备要重配

**换浏览器或清缓存后照片需要重新加载。** 因为只存了「哪个条目用哪张图」的对应关系，图片文件本身始终在你本地磁盘上 —— 这也是它不占代码体积、不上传服务器的原因。

### ⚠️ 用 `file://` 打开时，多个副本会共用一份存储

如果你在本地留了好几份副本（比如做了两个主题不同的榜单），这一条要特别注意。

浏览器把所有 `file://` 页面视为**同一个源**，共用一份 localStorage。实测确认：在 A 文件的页面里写入数据，导航到另一个目录的 B 文件后能直接读到。后果是两份榜单的数据会互相覆盖；如果两份的 `DATA_VERSION` 不同，打开其中一份还会把另一份的数据清掉。

稳妥做法二选一：

- **只保留一份在用**，其余归档压缩起来
- **改用本地服务器**，让每个副本有自己的端口：

```bash
cd 你的项目文件夹
python -m http.server 8000
```

不同端口属于不同的源，数据自然隔离。这也顺便解决了某些浏览器对本地文件的其它限制。
